## Deployed changes

- Actual processing status and failure details in metadata, plus inspect and
  repair tools. Daily agents are explicitly authorized to recover private
  failed/stalled uploads outside the Monday batch.
- MP4 retention until confirmed processing; schedule reconciliation back into
  the queue; resumable repair identity, private replacement validation,
  guarded deletion, and preservation of original editable status fields.
- Thumbnail previews use owner API rendition URLs, with lower-resolution
  fallback when max resolution is unavailable.
- Hourly Data API snapshots and measured 24/48-hour counter changes. Missing
  baselines remain unknown; subscriber counts are labeled as rounded.
- Independent revenue and engagement freshness; fractional watch hours;
  no RPM calculation across different reporting cutoffs.
- Studio readings retain source, observed time, period, rounding, missing
  values and collector errors. The deterministic Playwright collector reads
  visible cards; it does not call undocumented Studio APIs.
- Title/thumbnail changes retain before/after details and measured baselines.
  Agents must wait for post-change coverage and adequate exposure.
- Default reports return 20 videos with explicit coverage counts to reduce
  repeated large tool payloads. Larger limits remain available.
- Atomic JSON persistence and Chromium setup in CI for browser tests.

The approved server deployment is now managed by
`homelab/flux/clusters/azalab-0/manifests/apps/clipy/browser.yaml`: a
persistent Chromium profile on a 5Gi PVC, hourly collection (five-minute
retries while unavailable), and limits of 2Gi browser RAM plus 512Mi collector
RAM. There is no public Service, Ingress or hostPort. Browser UI access uses
SSH/Kubernetes port forwarding; CDP uses pod-local loopback. Network policy
denies ingress and private network egress, allowing cluster DNS and outbound
public HTTP/HTTPS. The browser image is pinned, service-account tokens are not
mounted, and stale Chromium lock files are cleared only after the previous
browser stops under the Recreate deployment strategy.

## Further improvements

1. Prefer native concurrent title/thumbnail A/B tests on eligible channels.
   YouTube chooses results using watch time, and sequential title swaps can
   confound the effect of the change with audience/timing changes:
   [YouTube A/B testing](https://support.google.com/youtube/answer/16391400).
   Studio visibly offers A/B Testing on JBlow. No native test was started.
2. Keep low-exposure Science/Philosophy tests inconclusive and preserve speaker
   diversity until there is meaningful watch-time evidence.
3. Archive daily run summaries and errors beyond Kubernetes pod retention.
   Persist enough evidence to inspect quota/auth/processing failures later.
4. After the dedicated Studio login works, consider automating the remaining
   monetization step through Studio. The collector currently reads only.
